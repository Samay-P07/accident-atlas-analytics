Project Overview & Objectives

Transforming raw, heterogeneous German traffic safety open datasets into an analytical web service

The Problem

Fragmented & Raw Open Data

  • ✕ Heterogeneous CSV Structures: Unfallatlas point records vs Destatis regional population statistics use incompatible geographic representations.
  • ✕ Inconsistent Regional Keys: AGS keys vary in length (2-digit states, 5-digit districts, 8-digit municipal codes) leading to relational join failures.
  • ✕ Locale & Format Hurdles: Coordinates formatted with German decimal commas (`"13,73726"`) causing database float parser crashes.
The Solution

Unified 3-Tier Web Engine

  • ✓ Automated ETL Pipeline: `import_data.py` standardizes 8-digit AGS keys (`.zfill()`), normalizes floats, and enforces relational integrity.
  • ✓ FastAPI REST Service: Serves 7 REST endpoints executing dynamic PostgreSQL queries with zero hardcoded metrics.
  • ✓ Dark Glassmorphism SPA: Interactive Tailwind UI with JSON response modal overlay for transparent examiner verification.

Automated ETL Data Ingestion Pipeline

Parsing, cleaning, harmonizing, and loading raw CSV datasets into PostgreSQL (`import_data.py`)

Ingested Open Datasets

German Open Data Sources

Unfallatlas (2023 & 2024) Fact Source

Point-level accident logs containing month, hour, severity, lighting, bike/pedestrian participation, and WGS84 coordinates.

Destatis GV-ISys / GENESIS Dimension Source

`accident_per_10000_per_city_2.csv` registering official municipal keys (`schluessel`), region names, and population metrics.

Legal Attribution: Data license Germany – attribution – version 2.0 (dl-de/by-2-0)
Automated Execution Pipeline

7-Step Execution in `import_data.py`

Step 1 Archive Extraction: Unzips raw `.zip` archives from `./raw_data` to `./extracted_data`
Step 2 Schema Initialization: Executes DDL statements to create `provenance`, `regions`, and `accidents`
Step 3 Provenance Ingestion: Registers `dl-de/by-2-0` licensing details in `provenance` metadata table
Step 4 Destatis Data Mapping: Parses municipal census CSV, calculates baseline population, inserts into `regions`
Step 5 AGS Harmonization: Concatenates `ULAND(2) + UREGBEZ(1) + UKREIS(2) + UGEMEINDE(3)` with `.zfill()`
Step 6 FK Safety Guard: Auto-creates missing `Region_{ags}` entries to prevent foreign key errors
Step 7 Idempotent Batch Load: Converts German decimal commas to floats and loads accident rows into PostgreSQL

app.py — Client JavaScript Query Trigger Vanilla JS & Fetch API 
async function triggerQuery(endpoint, questionTitle) {
    const modal = document.getElementById("result-modal");
    const modalTitle = document.getElementById("modal-question-title");
    const modalBody = document.getElementById("modal-json-output");

    modalTitle.innerText = questionTitle;
    modalBody.innerHTML = '// Fetching statistics from database...';
    modal.classList.remove("hidden");

    try {
        const response = await fetch(endpoint);
        const data = await response.json();
        // Render pretty JSON in overlay modal
        modalBody.innerHTML = JSON.stringify(data, null, 4);
    } catch (error) {
        modalBody.innerHTML = '// Execution error: ' + error;
    }
}

Key Technical Challenges & Design Decisions

Architectural solutions for open data harmonization and academic submission compliance

1. 8-Digit AGS Padding & Key Uniformity

Key Harmonization

German administrative keys vary from 2-digit states to 8-digit municipal codes. Standardized via `.zfill()` into uniform 8-character foreign key strings to enable instant hierarchical wildcard matching (`ags LIKE '14%'`).

Solution: ul_str(2) + ur_str(1) + uk_str(2) + ug_str(3)

2. Foreign Key Referential Safety Guards

Database Integrity

Raw accident records contained municipal codes absent in Destatis regional baseline tables. Engineered auto-provisioning logic inside `import_data.py` to insert synthetic `Region_{ags}` rows to prevent FK constraint failures.

Solution: INSERT INTO regions ON CONFLICT DO NOTHING

3. German Comma Coordinate Parsing

Data Cleaning

Unfallatlas CSVs formatted WGS84 spatial coordinates using German decimal commas (e.g. `"13,73726"`). Applied string replace operations before casting to PostgreSQL `NUMERIC` floating point types.

Solution: str(val).replace(',', '.') -> NUMERIC

4. OPAL & Zero-Hardcoding Compliance

Academic Rubric

Met strict < 10 MiB OPAL submission requirement by serving styling assets via lightweight CDN links and running local PostgreSQL queries rather than bundling heavy static JSON databases.

Solution: 100% Dynamic SQL + CDN CSS Assets
